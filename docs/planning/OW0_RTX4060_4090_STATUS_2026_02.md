## 1. 当前实现状态（OW0）

### 1.1 状态结论

1. **已实现**：OWF（Owner-World + two-level frontier）路径已在 `FQPTBaselineManager` 中落地。  
2. **已接线**：CLI、benchmark 输出、test 开关均已接线。  
3. **默认关闭**：`--fqpt_enable_world_owner=false` 时保持 legacy FQPT 行为。  
4. **可回退**：OWF 与 legacy 通过运行时分流，随时可切回。

### 1.2 开关与统计

- 开关：
  - `--fqpt_enable_world_owner`（`apps/sac_benchmark.cpp`）
- OWF 统计：
  - `fpop`（frontier pop 次数）
  - `fscan`（平均 frontier L1 扫描步数）
- 接口锚点：
  - `include/solver/gpu/batch_probe_manager.h::FQPTControl (line hint: 1075)`
  - `include/solver/gpu/batch_probe_manager.h::FQPTStatistics (line hint: 1144)`
  - `src/solver/gpu/batch_probe_manager.cu::FQPTBaselineManager::LaunchKernel (line hint: 2973)`

### 1.3 OWF 机制摘要

- 调度：`owner(world)=world%gridDim.x`，warp-per-world 固定映射。
- frontier：L0=`frontier_A`，L1=`frontier_B`（two-level bitset）。
- 检查：warp-only check（`__syncwarp` 路径），避免 block barrier 交叉阻塞。
- 统计：每 world 结束后 lane0 flush 到全局计数（降低原子频率）。

## 3. 为什么 4060/4090 需要单独策略（DDR/PCIe 角度）

本节是**推断 + 代码证据**，不是 4060/4090 已测结论。

核心判断：当前实现仍大量依赖 Unified Memory 与同步栅栏。在 Jetson UMA 上代价模型与离散卡不同；迁移到 4060/4090（PCIe）后，若访问/迁移边界控制不当，CPU-GPU 往返与 page migration 风险会被放大。

关键证据锚点：

- `src/solver/gpu/batch_probe_manager.cu:2562`：FQPT 路径大规模 `cudaMallocManaged`。  
- `src/solver/gpu/batch_probe_manager.cu:2797`：snapshot 后 `cudaDeviceSynchronize`。  
- `src/solver/gpu/batch_probe_manager.cu:2817`：legacy 路径 host 循环 world 初始化并 `cudaMemcpy`。  
- `src/solver/gpu/batch_probe_manager.cu:3025`：kernel launch 前同步。  
- `src/solver/gpu/GModel.cu:3973`：GModel 基础资源 `cudaMallocManaged`。

工程含义：

1. OW0 已显著去掉 FQPT 的队列/锁热点，但尚未消除全部“host orchestration + UM”风险。  
2. 4060/4090 上若要继续拉开与 Stage2 的差距，下一步更可能在“内存路径与驻留策略”而非纯算子上。

## 5. 给其他模型的“策略任务书”

目标：设计“4060/4090 上更快”的下一步策略，必须满足：

- default-off；
- 可回退；
- soundness 不变（UNKNOWN 不删值）；
- 不破坏 Stage2 稳定路径。

至少比较三类方案：

1. `S1` 内存路径  
从 UM 迁移到更显式的 H2D/D2H 与常驻策略；必要时引入预取/分层缓存策略。  
重点评估：同步点数量、host 参与度、跨 PCIe 传输频度。

2. `S2` 调度路径  
保留 owner 思路，但优化负载均衡（避免静态映射拖尾）。  
重点评估：world 工作量偏斜下的尾部等待与吞吐损失。

3. `S3` 内核路径  
减少 lane0 串行 frontier set 开销（按 `word_id` 聚合写回）。  
重点评估：高 degree 变量场景的串行瓶颈是否成为新上限。

对方输出建议格式：

- 方案概述（为什么适合 4060/4090）  
- 改动范围（接口/内核/统计）  
- 风险与回退  
- 验收门槛（正确性 + 性能 + 退化触发）
